# Build Notes: Turf Installation SEO + AEO Plan

How the owner's install SEO/AEO spec (Nov 24, 2026) maps onto this repo, and
where each phase stands. Read with `CLAUDE.md` (project rules) and
`docs/migration-requirements.md`.

## What this repo is

| Spec concept | This repo |
|---|---|
| Framework | Plain PHP, no framework, no build step. `index.php` front controller + `.htaccess` rewrites. Local dev: `php -S localhost:8000 dev_router.php`. |
| Pages / content | One route per URL in `config/routes.php` (title, meta, template, schema types). Body copy in `content/pages/{slug}.php`. |
| Layouts | `templates/page.php` (hero band pulled from the page's leading `<img>` + `<h1>`), `home.php`, `article.php`. Header/footer/nav in `includes/`. |
| Metadata | `includes/seo-head.php` (title, meta, canonical, robots, OG, hero preload). |
| Schema | `includes/schema.php`, one JSON-LD `@graph` per page. |
| Sitemap | Static `sitemap.xml`, regenerated by `php bin/generate-sitemap.php`. |
| Redirects | `config/redirects.php` (301 map) + host/HTTPS rules in `.htaccess`. |
| NAP / tracking IDs | `config/business-info.php` (single source of truth). GA4 + HubSpot in `includes/tracking.php`. |
| CRM | Zoho via `includes/zoho-crm.php` (plain curl). |

## How the spec's pieces were implemented

| Spec | Implementation |
|---|---|
| `site-facts` register + `{{fact.x}}` tokens | `config/site-facts.php` + `includes/facts.php`. Page copy calls `fact('id')` (escaped text) or wraps whole sentences in `fact_ready('id')`; placeholders (`value => null`) hide their block instead of printing. PHP calls instead of `{{tokens}}` because the repo's content files are PHP. |
| "Build-time warning" for unconfirmed facts | No build step exists, so: `php bin/check-facts.php` lists each unconfirmed fact and the pages using it. Never blocks anything. |
| FILE blocks (frontmatter) | Frontmatter goes into the page's entry in `config/routes.php` (`title`, `description`, `breadcrumb`, `service_schema`, `cta`). Body goes into `content/pages/{slug}.php`, ported word for word. |
| `[FAQ]` blocks | `render_faq([...])` in `includes/faq.php`. One array renders the visible `<details>` accordion (in the HTML, not loaded on click) and the FAQPage JSON-LD, so they always match exactly. |
| `[CTA]` component | `render_cta($route)` in `includes/page-cta.php`. Routes with `'cta' => 'installation'` also switch the hero button, bottom banner and mobile sticky bar to the install estimate. |
| BreadcrumbList | Every page below `/` (`includes/breadcrumbs.php`). Routes may declare a `breadcrumb` trail, which also renders a visible breadcrumb. |
| Links to pages from later phases | `maybe_link()` / `route_exists()` in `includes/links.php`. Text renders unlinked (or the sentence is hidden) until the target route exists, so no phase ships a dead link, and links turn on automatically when the page ships. |
| Section 4 slugs | `/turf-installation/cost` etc. are just new keys in `config/routes.php`; no new directories needed. |

## Findings to act on (not code)

1. **Bingbot gets 403 from Hostinger.** ChatGPT search leans on Bing's index. My test used a Bingbot user agent from a non-Microsoft IP, so Hostinger may only be blocking *fake* Bingbots. Verify with Bing Webmaster Tools > URL Inspection > Live URL once the site is verified there. If real Bingbot is blocked, check hPanel > Security (bot protection / AI crawler settings).
2. **GPTBot gets 429 (rate-limited).** OAI-SearchBot and ChatGPT-User (the ones that power ChatGPT answers and links) get 200. GPTBot is OpenAI's training crawler; being throttled there is lower priority but worth knowing.
3. **Search Console baseline (last 28 days, the most Windsor's trial allows):** install demand is barely visible yet. "artificial turf installation" 9 impressions at position 5.3; "turf installation near me" 2 at 6.5; Frisco and Celina install queries show up at position 50+, and neither city is in the 8-city plan. Full list in `docs/install-seo/gsc-baseline-2026-11-24.md`.
